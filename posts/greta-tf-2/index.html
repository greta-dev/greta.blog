greta 0.5.0

greta 0.5.0 moves greta onto TensorFlow 2. The modelling code you write is unchanged, but the optimiser interface, installation, and print methods all got an overhaul.

We are thrilled to announce the release of greta 0.5.0. greta lets you write statistical models directly in R and fit them with MCMC, using TensorFlow and TensorFlow Probability to do the heavy lifting.

install.packages("greta")

This release has been a long time in the making: greta now runs on TensorFlow 2. For most users, the models you write should work exactly as they did before. But this was a substantial internal change, and it comes with a reworked optimiser interface, a much better installation experience, and nicer printing. You can see the full list of changes in the release notes.

Below we cover what you may need to change, and then what is new. We will refer to TensorFlow as TF from here on.

Migrating to 0.5.0

Defunct optimisers

TensorFlow no longer supports a number of the optimisers greta used to expose, so these are now defunct:

powell(), cg(), newton_cg(), l_bfgs_b(), tnc(), cobyla(), and slsqp().

These functions still exist, so calling one gives you a proper error rather than “could not find function”:

opt(m, optimiser = slsqp())
#> Error:
#> ! The optimiser, `slsqp()`, is defunct and has been removed in greta 0.5.0.
#> Please use a different optimiser.
#> See `?optimisers` for detail on which optimizers are removed.

If you were using one of these, switch to one of the optimisers that remain, such as adam() or gradient_descent(). See ?optimisers for the full list.

momentum() is folded into gradient_descent()

The standalone momentum() optimiser is also defunct. Momentum is now an argument to gradient_descent(), which also gains nesterov:

Before:

opt(m, optimiser = momentum(learning_rate = 0.01, momentum = 0.9))

After:

opt(m, optimiser = gradient_descent(learning_rate = 0.01, momentum = 0.9))

rms_prop() renames decay to rho

Before:

opt(m, optimiser = rms_prop(decay = 0.9))

After:

opt(m, optimiser = rms_prop(rho = 0.9))

rms_prop() also gains a centered argument, matching the TF documentation.

Other things that may affect you

  • greta now requires R 4.1.0 or later.
  • install_greta_deps() no longer takes method, conda, or manual arguments; the first two were never used.
  • The greta_nodes_install_*() and greta_nodes_conda_*() options are defunct.

Why TensorFlow 2

Google released TF 2 in September 2019. The headline change was how TF executes code. TF 1 used what was called “graph mode”: you described a static computation graph up front, then handed it to a session to run. TF 2 uses “eager mode” instead, where operations are evaluated immediately as they are called, much like ordinary R or Python code. Graphs did not go away, but they became something you opt into for performance rather than the only way to work.

For greta this was both a large change and a small one. Internally, a great deal of code had to change, because greta’s whole approach is to build up a graph of your model and then hand it to TF. Moving from graph-based execution to eager execution meant rewriting how that graph is constructed and evaluated. Outwardly, though, the greta code you write is the same:

library(greta)

# data
x <- as_data(iris$Petal.Length)
y <- as_data(iris$Sepal.Length)

# priors
int <- normal(0, 5)
coef <- normal(0, 3)
sd <- lognormal(0, 3)

# likelihood
mu <- int + coef * x
distribution(y) <- normal(mu, sd)

m <- model(int, coef, sd)
draws <- mcmc(m, n_samples = 1000)

The reason for going through all of this is that TF 1 was reaching end of life, and staying on it meant greta could not use anything new. Being on TF 2 puts greta back on a supported foundation.

New optimiser options

Moving to the current TF optimiser interface also brought new options:

  • gradient_descent() gains momentum and nesterov arguments (docs).
  • adagrad() gains an epsilon argument.
  • adam() gains an amsgrad argument (docs).
  • ftrl() gains l2_shrinkage_regularization_strength and beta.
  • Two new optimisers: adamax() and nadam().

Installation revamp

Installation should now tell you more about what it is doing, and fail more gracefully when something goes wrong. The intention is that it should just work, and if it does not, that you get useful advice about where to look.

The new greta_deps_spec() gives you one object for specifying which versions you want, rather than a scattering of arguments:

install_greta_deps(
  deps = greta_deps_spec(
    tf_version = "2.15.1",
    tfp_version = "0.23.0",
    python_version = "3.11"
  )
)

Not every combination of TF, TF Probability, and Python works together, so greta now checks your request against a table of known-good combinations, shipped as the greta_deps_tf_tfp dataset. If you ask for something that will not work, greta tells you before it starts installing rather than after.

Alongside this:

  • Installation now writes to a single log file. Set its location with greta_set_install_logfile(), write it with write_greta_install_log(), and open it with open_greta_install_log(). The log goes to a sensible per-user location via tools::R_user_dir(), so it can always be found.
  • destroy_greta_deps() removes miniconda and greta’s Python conda environment, for when you want to start over completely.
  • greta_deps_receipt() reports the TF, TF Probability, and Python versions actually installed, without validating them against greta’s supported range. This means it still works when you have something newer than greta officially supports.
  • install_greta_deps() and reinstall_greta_deps() gain a restart argument to restart R for you once installation finishes.
  • Installation processes now have a default five minute timeout, so a stalled install does not hang forever.
  • greta_sitrep() now checks for installations of Python, TF, and TF Probability.

Better printing

MCMC output and greta arrays both used to flood the console. They now have print methods that keep things to a readable size, and you can control how much you see with the n argument:

print(draws, n = 5)

Minor improvements

  • The slice sampler no longer requires precision = "single" to work.
  • is.greta_array() and is.greta_mcmc_list() are now exported.
  • Fixes to the Wishart and LKJ correlation distributions, including a bug where the log probability could return NaN, and a fix for lkj_correlation() so that it now works with unknown dimensions.
  • A fix for a dimension error in matrix multiplication that occurred before coercing to a greta array.

What this unlocks

Now that greta is on TF 2, we can start taking advantage of what is available in modern TF and TF Probability. Some of the things we would like to explore:

  • the No-U-Turn Sampler (NUTS)
  • faster tuning during warmup
  • an interface for marginalisation
